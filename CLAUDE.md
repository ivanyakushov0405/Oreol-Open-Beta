# Ореол

Мессенджер «для закрытого показа»: серверы с текстовыми и голосовыми каналами, личный профиль, звонки с камерой и демонстрацией экрана. Прод: https://new.halomvp.ru.

## Устройство

- `main.py`: весь бэкенд в одном файле. FastAPI, SQLite (`chat.db`), вложения в S3 (Timeweb), голос через LiveKit. Отдаёт собранный фронтенд из `web/dist` (SPA: адреса страниц получают `index.html`).
- `web/`: React 18 + Vite + TypeScript, без UI-библиотек и роутеров.
  - `src/app/`: корень (`App.tsx`), общее состояние (`useAppState.ts`), роутинг на History API (`router.ts`), все стили в одном `styles.css`.
  - `src/layout/desktop` и `src/layout/mobile`: две раскладки. Мобильная со своими свайпами, шторками и виджетом звонка.
  - `src/features/*`: чат, голос, настройки, профиль, участники, уведомления.
  - `src/shared/`: API-клиент (`api.ts`), типы (`model.ts`), переводы (`i18n.ts`, `en.ts`), иконки, звуки, общие UI-компоненты.
- `deploy/`: compose, nginx и LiveKit для прода, инструкция в `deploy/DEPLOY.md`. Визуальная концепция в `DESIGN.md`.

## Запуск

- Бэкенд: `.venv/Scripts/python.exe main.py` (порт 8000). В превью это конфигурация `backend` из `.claude/launch.json`. Бэкенд отдаёт `web/dist`, поэтому после правок фронтенда нужна сборка.
- Фронтенд с горячей перезагрузкой: `npm --prefix web run dev` (порт 5173, `/api` проксируется на 8000).
- Сборка и проверка типов: `npm --prefix web run build` (`tsc -b && vite build`). Отдельного линтера нет.
- Настройки берутся из `.env` в корне (пример в `.env.example`). Без S3-ключей не работают вложения, без LiveKit не работает голос.

## Деплой

Docker-образ собирает фронтенд и копирует только `main.py`, `requirements.txt` и `web/dist`. Версии Python-пакетов и образа LiveKit закреплены, обновлять их осознанно.

## Безопасность

- Сессия живёт в HttpOnly-куке `oreol_session`, 30 дней с последнего использования. Bearer-заголовок принимается только для переноса старых токенов и для скриптов. Изменяющие запросы с кукой проходят проверку источника (`same_origin`), WebSocket тоже.
- CSP и заголовки безопасности ставит middleware `security_headers`. Хеш встроенного скрипта темы из `web/index.html` считается автоматически. Новые внешние источники (скрипты, шрифты, картинки) нужно добавлять в `page_csp()`.
- Превью ссылок ходит только в публичный интернет: проверка адреса и подключение используют один ответ DNS, картинки отдаются через подписанный прокси `/api/link-image`.
- Загрузки проверяются по содержимому (Pillow, заголовки MP4/WebM), не по Content-Type. Лимиты размеров и пропорций в начале раздела вложений и в `PROFILE_IMAGE`.
- `/clear_chat/{room}` работает только с `ADMIN_TOKEN`. Секреты (`.env`, токены) в чат и в коммиты не выводить.

## Правила работы

- Коммитить и пушить только по команде пользователя. Мелкие правки отдельно не коммитить.
- Интерфейс на двух языках. Исходный текст пишется по-русски внутри `t('...')` (подстановки `{0}`, множественное число через `plural()`), английский перевод добавляется в `web/src/shared/en.ts` с тем же ключом. Ошибки API сервер отдаёт по-русски, клиент переводит их через `serverText()`: новую ошибку тоже добавить в `en.ts` (с числами в `EN_PATTERNS`). Язык хранится в `localStorage` (`oreol.lang`), смена перезагружает страницу.
- Комментарии в коде на английском, коротко и только там, где без них непонятно «почему». Историю правок («раньше было так») в комментарии не писать. Длинное тире (—) не использовать ни в коде, ни в комментариях.
- В CSS писать только `backdrop-filter` без `-webkit-backdrop-filter`: префикс добавляет сборка (Lightning CSS в Vite 8), а пара «без префикса, затем с префиксом» при минификации схлопывается в один `-webkit-`, и в Chrome размытие пропадает.
- Производительность на телефоне важна: не вешать `:has()` на `body` и крупные контейнеры, не анимировать размытие и размеры, держать ленту чата оконной (`MessageList.tsx`, лимит строк в DOM).
- Виджет звонка на телефоне: всё, что открывается поверх экрана, размещать внутри этого экрана (`.m-full`, `position: absolute`), а не `position: fixed` на весь экран, и отступать сверху через `--sat` (это safe area плюс высота виджета `--call-h`). Тогда виджет остаётся сверху, а шапка панели совпадает с шапкой экрана. Проверять с активным звонком, с развёрнутым виджетом и со свёрнутым в пилюлю.
- Анимации на телефоне в стиле свайпа (`MobileHead.tsx`, `head-bump-a`, `sw-in`/`sw-out`, `.group.gone`, `head-pop-in`):
  - шапка стоит на месте, кнопка «Назад» и плашка заголовка только слегка «приседают» (scale около .96 и обратно), без прыжков и сдвигов;
  - меняется только текст, который действительно другой (старый уходит вверх, новый поднимается снизу), одинаковый не трогать;
  - группа кнопок уходит через прозрачность и уменьшение, остальное содержимое появляется по очереди;
  - тайминги мягкие, около 0.35–0.45 с;
  - закрытие собирать своими кадрами, а не `reverse()` открытия, иначе разворачивается и кривая и закрытие тянется;
  - `prefers-reduced-motion` не проверять: в Windows с выключенными эффектами анимации иначе пропадают совсем;
  - анимировать только transform, clip-path и opacity.
- Свайп «назад» на телефоне (`layout/mobile/swipes.ts`):
  - Верхний экран едет за пальцем, его шапка стоит на месте. Экран должен быть `.m-slide` прямо в `.m-stage`, а `.m-head` прямо в экране: завершённый свайп нажимает его кнопку «Назад», закрытие идёт тем же `close()` с `.out`.
  - Под свайпом нижний экран проявляется через opacity и закрыт матовым слоем `.m-swipe-veil` (размытие как у прозрачного чата), который тает по мере свайпа. Тень под таб-баром во время свайпа видна.
  - Прозрачный верхний экран (настройки, участники) получает свой матовый `::before` с `backdrop-filter`, чтобы сквозь него нижний экран был только размытым. Размытие не вешать на сам экран: он станет корнем фона для своих стеклянных карточек, и Safari покажет их серыми.
  - Стекло не обрезать clip-path на обёртке вокруг него (тоже серое в Safari). Накрытые карточки настроек в покое прячутся clip-path на самих карточках, а во время свайпа видны целиком и проявляются через opacity под матовым слоем.
  - Экран с вкладками внутри (информация о чате): на первой вкладке и в поиске свайп вправо закрывает экран (`data-edge` на экране), на остальных листает вкладки.
  - Проверять отменённый и завершённый свайп в обеих темах: после них не должно оставаться inline-стилей и `.m-swipe-veil`.
- Визуальные изменения проверять в превью (десктоп и мобильная ширина, светлая и тёмная тема).
